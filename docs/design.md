# 設計ドキュメント

## アーキテクチャ概要

### 評価パイプライン

```
ドキュメント
    ↓
チャンク戦略（複数定義・切り替え可能）
    ↓
埋め込み生成（OpenAI API）
    ↓
ローカルベクトル検索（インメモリ / FAISS）
    ↓
検索精度メトリクス（Recall@k / MRR）
    ↓
LLM回答生成（OpenAI API）
    ↓
LLM as a judge評価
    ↓
実験結果として記録・比較
```

### 設計思想

- **プラガブル**：新しいチャンク戦略をインターフェースを実装するだけで追加できる
- **再現性**：実験IDと全設定を記録し、同じ結果をいつでも再現できる
- **可観測性**：実験の設定・メトリクス・生成物をすべて保存する

| Vitest | Bun/TypeScript環境との親和性・高速な実行 |

## コード品質方針

このプロジェクトでは以下3テーマを意識的に実践する。

### 1. エラーハンドリング

**方針**

- 内部関数は `Result<T, E>` 型で成功・失敗を明示的に返す
- `throw` はCLIの最上位ハンドラでのみ許容する
- エラーをカスタムクラスで分類し、原因を明確にする

**エラー分類**

| クラス | 対象 |
|---|---|
| `ConfigValidationError` | 設定ファイルのスキーマ違反 |
| `ChunkingError` | チャンク処理中の失敗 |
| `EmbeddingApiError` | OpenAI埋め込みAPIの失敗 |
| `LlmApiError` | OpenAI LLM APIの失敗 |
| `StorageError` | ファイルの読み書き失敗 |

### 2. 型設計

**方針**

- `any` の使用を禁止（ESLintで強制）
- 実験設定・メトリクスはすべて型で表現する
- Zodのスキーマ定義からTypeScriptの型を導出し、ランタイムと型定義を同期させる
- `unknown` を使い、型が確定してから処理する

### 3. テスト戦略

**方針**

- 外部API（OpenAI等）はすべてモック化して単体テストを書く
- チャンク戦略の単体テスト：入力テキスト→チャンク結果を検証
- 実験フローの統合テスト：モックAPIで全体フローを検証
- カバレッジ目標：80%以上

## 実装フェーズ

### Phase 1：基盤 + チャンク戦略

- プロジェクト構造・設定スキーマの定義
- チャンク戦略のインターフェース設計
- 固定長・文単位・セマンティックの3戦略を実装
- チャンク結果のJSON Lines保存
- **品質重視ポイント**：型定義・Result型・チャンク戦略の単体テスト

### Phase 2：埋め込み + 検索精度

- OpenAI APIを使った埋め込み生成
- インメモリベクトル検索の実装
- 検索精度メトリクス（Recall@k / MRR）の計算
- **品質重視ポイント**：APIエラーハンドリング・APIモックを使ったテスト

### Phase 3：LLM評価ループ

- テストクエリ＋正解データセットの形式定義
- LLM回答生成の実装
- LLM as a judge評価の実装
- **品質重視ポイント**：評価結果の再現性・統合テスト

### Phase 4：実験管理・比較

- 実験結果の一覧表示・比較
- メトリクスの集計・レポート生成
- **品質重視ポイント**：データ形式の後方互換性
